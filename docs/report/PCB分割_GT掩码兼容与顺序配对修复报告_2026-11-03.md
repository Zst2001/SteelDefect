# PCB 分割 GT 掩码兼容与顺序配对修复报告

日期：2026-11-03。结果：**PASS**。

## 1. 问题原因

只读检查用户提供目录 `F:\360MoveData\Users\40336\Desktop\light\PCB_seg\mask` 中的 `99-10e302a02-2-8-9_10-1_Cur.png` 至 `..._10-5_Cur.png`，五张均为：

- 220×220、8-bit、PNG color type 3，Pillow 模式 `P`（调色板）。
- 实际使用索引为0和215，分别对应黑色 `[0,0,0]`、白色 `[255,255,255]`。
- 属于确切的黑白二值掩码，但旧前端只接收8位单通道PNG，旧批量后端也只允许 `L` 模式，因此在配对之前就被格式校验拒绝。

本次报错不是 `_mask` / `_gt` 文件名匹配导致；同时按用户要求改善了不同名文件的配对体验。

## 2. 修复内容

### 掩码格式兼容

PCB批量上传现在支持1位、灰度、黑白调色板、三通道一致的黑白RGB二值PNG。后端读取实际颜色而不是将调色板索引直接当作标签，规范化为 `L` 模式0/1 PNG供冻结、Worker及指标使用。原文件编码、SHA和大小记录在GT元信息中，保存文件身份单独记录。

保留同尺寸、单帧、不透明、二值及大小检查。彩色多类别、多灰阶、实际透明/半透明、16位、RGBA/LA仍明确拒绝。没有按阈值猜测、不拉伸GT，也不把任意非零颜色都当成缺陷。原生单图旧接口契约、模型输入和冻结权重不变。

用户五个原始mask只读归一化结果全部通过：规范化后的前景像素与原实际黑白颜色一致，差异像素均为0；再次经过Worker相同解码流程后字节保持一致，原文件SHA未改变。没有改写数据集目录。

### 配对交互

1. 文件名可以不同；保留唯一同名候选自动配对作为便利方式，不要求用户遵循命名后缀。
2. 新增“按列表顺序配对”：明确按页面当前原图列表与掩码列表的顺序关联，不宣称操作系统文件选择顺序就是数据集语义对应关系。
3. 原图与掩码均显示序号；每张原图可单独点击“选择掩码”，也可通过下拉框调整，并可预览已配对的掩码。
4. 数量不等时仅配对已有对应项，其他原图保留无GT；未关联掩码显示提醒且不上传，不阻碍无GT分割。无GT仍不计算指标。
5. 尺寸不匹配或同一GT重复关联两图时仍阻止错误配对提交。已明确纠正的错误会清除，不会因旧错误消息永久阻塞。
6. 更换一张掩码只影响目标原图。若原掩码暂被其他行引用，会保留该文件；不会意外使其他原图丢失GT。十张满额下正常替换可用，共享冲突需先纠正。

### 页面颜色

四个模块标题由深青改为浅蓝 `#4a83bd`，保留上轮两行两列等宽对齐布局及移动端单列。

## 4. 使用方式

刷新PCB分割工作台后重新选择文件：

1. 上传原图。
2. 批量“添加 GT 标签”，然后点击“按列表顺序配对”；或直接在对应原图行点击“选择掩码”。
3. 核对序号、文件名及预览，必要时用下拉框更正。两个目录的文件排列可能不同，不应仅凭数量相同认定配对正确。
4. 选择模型并提交。未配对的原图可以正常分割，但不出指标。

实际图片与掩码的语义对应关系由用户确认，本次没有重命名或猜测配对原始数据集。
