# PCB 分类工作台优化与图片格式兼容报告

日期：2026-11-03

## 1. 完成情况

已按 PCB 分割工作台的风格调整分类上传页面，并实现全部现有分类模型的多选提交；上传格式兼容扩展到六种常见静态图片。

本次实际修改前端和上传适配代码。没有修改模型权重、CPU 准入回执、冻结推理代码、分类标签、指标政策、首页、侧栏或 `.env`，没有训练、Git 提交或推送。既有工作区修改保留。

## 2. 页面与操作

入口：`/inspect/pcb/classification`。

- 桌面采用两行两列：上方为上传图像、选择分类模型，下方为分类范围、提交摘要；标题使用与分割页一致的浅蓝色。
- 上传区域整块可点击，也支持 Enter、空格和拖入图片；删除原来的“选择 ROI”按钮。已选图片后再次点击该区域即可更换，另保留移除操作。
- 展示原文件名、尺寸和大小，支持重新选择同一文件；手机端自动变成单列。
- EfficientNet-B0、MobileNetV3-Small 以纵向复选卡片展示，显示参数量和 CPU 推理说明，支持“全选全部模型”“取消全选”。默认选中 EfficientNet-B0。
- 同一张图片可以同时使用两个模型。提交摘要显示图片数、模型数与任务数。
- 单模型提交后沿用原有任务详情页；多模型提交后保留在工作台，分别提供各模型任务的结果入口，并明确显示“提交时状态”。没有将任务创建成功冒充推理完成。

仍为单张图片分类，本次没有扩展多图片批处理。拖入多张时给出明确提示，不静默丢弃其他文件。

## 3. 多模型任务与重试

复用现有单模型任务接口，不新增数据库结构或多模型推理协议：

1. 图片上传一次，取得共享的分类批次 ID。
2. 为每个选中模型分别调用现有创建任务接口。
3. 每个“批次＋模型”保留独立幂等键。
4. 部分模型提交成功时保留任务入口；重试只补交尚未确认的模型。
5. 响应不确定后再次提交、A→B→A 切换模型均复用原请求身份，避免重复创建。

已确认的全部所选任务不允许重复提交；更换图片会开始新批次。关闭页面后的任务继续由既有队列处理，可在历史记录中找到。

## 4. 图片兼容范围

| 项目 | 本次行为 |
|---|---|
| 文件格式 | 静态 PNG、JPEG、WebP、BMP、TIFF、GIF |
| 文件类型判断 | 根据实际图片内容，不再要求扩展名和浏览器 MIME 完全一致；支持无扩展名的合法图片 |
| 文件大小 | 单张上限由 2 MiB 放宽到 **10 MiB** |
| 尺寸 | 不要求固定尺寸，总像素仍不超过 **16,777,216（4096²）** |
| 常见颜色模式 | 支持普通彩色、灰度、调色板等格式，由服务端转换到既有模型输入 |
| EXIF | 支持有效 EXIF 方向自动校正 |
| TIFF 预览 | 浏览器无法预览时仍可选择，显示待服务端校验提示，不伪造缩略图 |
| 必要拒绝项 | 空文件、损坏文件、路径型文件名、超限图片、动画、多页文件、16 位/浮点等不支持的解码模式、SVG 等非支持格式 |

格式兼容不等于模型适用范围扩展。现有权重仍用于单缺陷局部图像的六分类，不包含正常类，不提供整板定位、自动裁框或分割；置信度不是准确率。

## 5. 保持冻结推理协议的方式

新增独立上传适配层 `apps/api/app/services/pcb_classification_uploads.py`，不修改参与准入源代码哈希的 `packages/infer/pcb_classification/` 文件。

- 对既有解码器可接受的 PNG/JPEG，原始字节和解码事实保持不变；原生 224×224 灰度 PNG 保持像素。
- 新格式、需校正方向或超过旧字节限额的图片，按既有灰度及双线性缩放规则转换，再保存为 224×224 灰度等价 RGB PNG。既有解码器会正确标记 `input_adapted=true`。
- Worker 仍只消费原有冻结 PNG/JPEG 契约，保持权重严格加载、归一化、六类输出校验和输入哈希检查。
- 新增 `source_image` 元数据，记录原文件名、格式、模式、尺寸、字节数、SHA-256、方向处理和转换说明；该信息随任务输入快照冻结。
- 需要转换时，存储的是转换后的任务输入；原文件保留来源元数据及哈希，没有额外保存原文件副本。任务结果中的输入哈希仍指向实际冻结字节。
- 旧任务没有 `source_image` 时继续兼容；未改旧任务或历史结果。
