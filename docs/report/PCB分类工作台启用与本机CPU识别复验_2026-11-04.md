# PCB 分类工作台启用与本机 CPU 识别复验

2026-11-04，本地站点的分类模型目录已恢复可用，两个已准入模型均在当前 RQ Worker 完成真实 CPU 推理。

## 故障定位

通过登录后的 Vite 代理读取分类模型目录，复现到 `enabled=true`、`available=false`。独立启动同一虚拟环境时，两份模型均通过准入。进一步在实际 Worker 中读取运行环境指纹，只有 `machine` 和 `processor` 与准入环境不同，这两项在旧进程中均为空。本机 Windows 系统记录的硬件标识与准入环境一致。

## 修复与生效

在 `apps/api/app/bootstrap.py` 增加 Windows 启动处理。Python 缺少 CPU 标识时，从本机系统注册表读取系统提供的架构和处理器名称，补充到当前进程缺失的环境变量，并刷新 Python 已缓存的空标识。API 和 Worker 随后按原校验流程核对准入回执。分类开关原本已打开，本次无需修改站点配置或回执。

API 热重载后重新读取模型目录。确认队列为空且 Worker 空闲后，向该 Worker 的独立控制台发送退出信号，待其正常退出，再从项目虚拟环境启动新 Worker。

## 实际验证

| 检查 | 结果 |
|---|---|
| 模拟 WMI 不可用并移除进程 CPU 环境变量 | 在 Windows 上复现两个空字段，启动修复后重新取得本机标识，两模型通过原准入校验 |
| 已登录的本地站点模型目录 | HTTP 200，开关与目录可用标记均为 true，两模型的 available 均为 true |
| 当前 RQ Worker | 通过队列执行目录检查，开关与可用标记均为 true |
| EfficientNet-B0、MobileNetV3-Small | 各完成一次合成图 CPU 推理，返回正确模型标识、六个有效概率及 224×224 预览。这两次检查用于验证可执行性 |
| PCB 分类隔离回归 | 61 项通过，2 项依赖弃用提示。[测试日志](pcb-classification-enable-20261104.log) |
| 工作台前端路由 | HTTP 200。浏览器自动化因无法可靠识别 Chrome 当前地址而结束，最终启用状态由站点的已登录模型接口与实际 Worker 验证 |

打开工作台后刷新，或点击“重新检查状态”。验收期间调用过内置开发账号 student 的登出接口，该接口会使当时该账号已有的登录会话失效。使用这个账号的浏览器如提示登录，请重新登录。
