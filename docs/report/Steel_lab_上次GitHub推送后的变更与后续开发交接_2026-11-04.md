## 3. 后续代码应接在哪一层

平台的主要调用关系仍是 Vue 3 / Vite → FastAPI → MySQL 持久化 → Redis / RQ → CPU Worker → 授权结果文件。**两种 PCB 任务共用平台基础设施，但多模型提交方式不同。**

**PCB 分割有服务端批次。** `PcbNewView.vue` 调用 `/api/scenes/pcb/segmentation/uploads/batch`，通过 multipart 的 `manifest` 明确关联原图和 GT。再调用 `tasks/batch` 创建“图片 × 模型”子任务。服务端复用一个私有 Dataset、一个父 DatasetVersion、每图一个子版本及各模型的独立 Task，无需新增表。页面从 `batches/{batch_id}` 查询状态和结果。原单图接口仍服务旧调用方。入口见 `apps/api/app/routers/pcb_segmentation.py`，业务逻辑见 **`apps/api/app/services/pcb_batch.py`** 的 `create_group`、`submit_group`、`get_group`。

**分割适配要保留坐标。** 原生 220×220 RGB 走原协议。批量路径可接收 8 位灰度图，小图补边，大图用 220 像素窗口、176 像素步长，融合重叠区概率再还原到原图坐标。单边最大 2048，单文件 10 MiB，整批 50 MiB，所有图片的窗口数乘选中模型数不超过 500。Grad-CAM 仅支持原生 220×220 RGB。在不支持的样本上保留分割结果及原因。见 **`packages/infer/pcb/tiling.py`** 的 `plan`、`predict_tiled`，以及 `apps/worker/pcb_segmentation.py` 的 `compute_adapted`、`run_pcb_body`。

**PCB 分类沿用每模型一个任务的接口。** `apps/web/src/views/pcb/PcbClassifyNewView.vue` 对同一张图只上传一次，为每个选中模型分别 POST 到 `/api/scenes/pcb/classification/tasks`。每个“批次＋模型”保存独立幂等键。一个创建成功、另一个响应不确定时，页面保留成功任务入口，只重试未确认模型。结果详情沿用已有六类分类协议，提交时显示的队列状态与推理完成分开。

**分类上传兼容位于准入模型之外。** **`apps/api/app/services/pcb_classification_uploads.py`** 的 `prepare_upload` 校验文件内容、总像素和单帧条件。已符合原契约的 PNG/JPEG 保留字节。其他受支持图片按需校正方向，按原协议灰度化、双线性缩放为 224×224，再编码为灰度等价 RGB PNG 供冻结解码器读取。保留原文件格式、尺寸、SHA-256 和转换说明；结果的输入 SHA 指向实际执行的冻结字节。旧任务没有 `source_image` 时也能读取。后续改上传兼容性，先检查这一层，避免无意更改参与模型准入哈希的文件。

第 4 个未跟踪产品文件是批次结果页 **`apps/web/src/views/pcb/PcbBatchView.vue`**，已由 `apps/web/src/router/index.ts` 接入 `/inspect/pcb/batches/:batchId`。其余改动包括单任务详情、历史重跑、前端类型，以及 Vite 对分割推理源码私有路径的拒绝规则。以上四个粗体新文件都是运行所需代码。

## 4. 已经遇到的问题，以及下次如何避免

| 出现过的现象 | 原因及当前处理 | 下次验收应做什么 |
|---|---|---|
| 实际黑白 GT 被报“须为 8 位单通道 PNG” | 报错发生在配对之前。用户的五张图是调色板 PNG，索引 215 实际代表白色。新批量路径按实际颜色验证二值性并规范化为 0/1。支持 1 位、灰度、黑白调色板和黑白 RGB。 | 用真实调色板样本比对转换前后前景像素，含黑白索引反转情形。校验同尺寸、不透明和二值性。不得用“非零都算缺陷”或缩放 GT 来让校验通过。 |
| 名称不同、文件排序不同，或改正配对后仍被旧错误拦住 | 列表顺序是用户选定的映射方式。最终提交按稳定 ID 和 manifest 关联。未配对掩码提示后不上传。修改某一行时保留其他行仍引用的文件。 | 用不同名、数量不等、同尺寸但内容不同的样本核对预览，并测试重复映射、错尺寸后纠正、换图后重新提交。 |
| 一个任务失败或提交响应丢失，重试容易生成重复任务 | 分割先保存子任务，再逐一投递。未知投递状态 `QUEUE_UNKNOWN` 不能盲目重发。分类按模型保留请求身份与已确认结果。显式重跑产生新任务，旧结果保留。 | 模拟 A 成功、B 超时，再次提交及 A→B→A 改选。核对任务 ID、上传次数和队列投递次数，同时检查其他成功项仍能访问。 |
| 新的横向结果页看似少图，或翻到另一张后仍显示旧指标 | 分割批次按**任务**分页，上限 100。返回的全局计数与页内样本汇总含义不同。前端跨页按样本合并、按任务 ID 去重，用样本 ID 保持轮询中的选择。 | 测试重跑导致跨页、连续切图、无 GT、缺 CAM 和单图层加载失败。无 GT 时禁用错误图并隐藏数值指标；概率图、CAM、配对 GT 各自有独立含义。 |
| 本机核验通过，网页却显示“PCB 分类暂未启用” | 11 月 4 日实际接口返回 `enabled=true`、`available=false`。实际 Worker 的 `machine`、`processor` 为空。共用启动代码 `apps/api/app/bootstrap.py::_restore_windows_cpu_identity` 从 Windows 系统记录补齐进程缺失字段，刷新空缓存，再执行原准入检查。 | 依次检查已登录站点模型目录、两个模型各自的可用标记、实际 Worker 运行环境与一次 CPU 前向。健康页或独立终端中的成功只能证明对应进程。切勿手改回执或在前端硬编码“已启用”。 |
| 导师只获授权一个子任务，批次页却可能暴露同批其他图片、统计或文件 | 当前查询按子任务授权过滤，文件经已有 TaskArtifacts 门禁，重跑也复用快照检查。 | 验证所有者、其他学生、导师单项授权、撤回后的列表和下载。运维测试使用专用账号，注意现有登出接口会使该账号已有会话失效。 |

## 5. 实验与产品边界

- 网站常驻 CPU，只做推理。新增实装能力以认可权重、本机准入和可重现推理为前提。学生插件仍由 Docker 隔离，Web 不导入学生 Python 源码。
- 钢铁公开演示只展示分割效果，不计算、持久化或展示精度。钢铁分割对照有配对 GT 才出参考指标，正式分割评测限 NEU-20。PCB 分割的 Dice、IoU、Precision、Recall 属于已配对图片的参考结果，不能写成整套数据集性能。
- PCB 分类以单个缺陷为主的局部图像为输入，六类中没有正常类。扩大上传格式没有增加整板定位、多图分类、自动裁框或分类 CAM。分类置信度不能当准确率。当前 PCB 批次分割也没有主动取消协议。
- 钢铁分类、PCB 分割与 PCB 分类在此基线前已实现。早期“仅钢铁分割可运行”的交接说明不代表当前工作区。钢铁目标检测、光伏等未实现入口不可据此开放。科研助手保留现有 harness 和显式专科选择，学术 RAG 继续遵守 `ippilab` 集合边界。
