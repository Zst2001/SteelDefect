## 已拍板

1. **同意后改当前这个 `ModelVersion`。** 追加适配并复检通过后，该版本留在**该学生模型中心**，状态为可运行，可直接用于之后的快速对比 / 正式评测，不必再传一份。
2. **`forward` 返回 tuple/list 时，固定取第 1 个张量作为主输出。** 预览必须写明；第一版不做选路。包装与 `packages/admit` 检查器同一规则。
3. **自动追加不改权重加载逻辑。** 不去掉 `module.` 前缀，不 `strict=False`。键集合对不上时，禁止靠放宽加载器绿灯。仅当后续增强项能证明「去掉 `module.` 后键集合完全一致」时，才可再开第二条可选白名单，仍 `strict=True`。
4. **正式名称：模型适配助手。**
5. **消融变体对齐（v0.4，来自 TSFNet 导入失败）。** 一份源码里多个已有 class / 注册表时，适配层必须按 checkpoint 的 `model_name` 包对应变体，而不是体量最大的统一类。已追加过适配层但包错了变体、随后 `load` 失败时，允许再同意一次：**只替换适配块内的构造目标**，仍不改原 class、不改 `.pth`、不改 `load_state_dict`。

---

## 1. 要解决什么问题

学生在 AutoDL 上已经把实验跑通，`.py` + `.pth` 在训练脚本里能构建、能加载、能前向。导入本站后仍可能显示「不能启动」，常见原因不是网络结构错误，而是训练脚本接口与本站插件契约不一致。

目标：在**不改网络结构、不重训、不改 `.pth`** 的前提下，补一层导入适配，使已训模型通过现有隔离检查后变为「可运行」，并作为该学生名下的可用模型版本保留。

非目标：代写网络、代修训练 bug、把本站改成兼容任意 `train.py`、静默改代码到绿灯。

---

## 2. 本站契约（适配的目标接口）

1. 单文件 `.py` + 单个 `.pth` / `.pt`。
2. 提供 `build_model(num_classes: int, in_channels: int = 3, **kwargs) -> nn.Module`（推荐）。构造函数吃不下 `in_channels` 时必须走包装，不能只改入口类名。
3. `forward` 主输出为 `B×C×H×W` logits。训练时若返回 tuple/list：**固定取第 1 项**（已锁定）。不得删原类辅助头。
4. 权重按检查器白名单加载，`strict=True`。**自动追加不改加载器**；去 `module.` 仅意见，不作为自动动作（已锁定）。
5. 静态扫描 + Docker 隔离不变；Web 进程不 `import` 学生 `.py`。禁止把联网下骨干当作适配手段。
6. 选包装目标时：若 checkpoint 带 `model_name`，且源码有字符串→类名的注册表（如 `MODEL_REGISTRY`），**必须包映射到的那个已有 class**。这不是改架构，只是选对已有变体。

预处理仍为 `neu_200`。第一版不改预处理。

## 4. 主流程

```text
学生上传 .py + .pth
    → 现有隔离检查（admit）
    → 成功：runnable，出现在该学生模型中心（助手不出现）
    → 失败：cannot_start
         → 模型适配助手归类（fail_stage + AST + 必要时 checkpoint.model_name / 注册表）
         → 白名单内：修改点 + 仅适配层的 diff
         → 同意 → 写入当前版本 model.py（原 class 不动）→ 更新哈希 → 重跑 admit
              通过：runnable，仍是这一条模型记录，可加入对比/评测
              失败：仍 cannot_start，展示新阶段
                   若新阶段是 load，且适配层构造类 ≠ 注册表映射类：允许再提案「只换适配层目标类」
                   禁止为绿灯改网络结构或放宽 load_state_dict
         → 不同意 → 源码不改，只留意见
```

## 5. 失败归类

### 5.1 可自动提案（同意后改当前版本的适配层）

| 失败 | 适配动作 |
|------|----------|
| 找不到 `build_model` / 指定类 | 末尾追加 `lab_build_model`，只传原类认识的参数。目标类优先：checkpoint `model_name` → 源码注册表 → 否则再按别名/体量启发式 |
| 构造函数 unexpected keyword（如 `in_channels`） | 同上包装 |
| `forward` 返回 tuple/list | 包装 `forward` **固定取第 1 个张量**作为主输出；预览必须写明 |
| 已追加适配层后 `load` 失败，且适配块内构造类 ≠ `model_name` 映射到的已有变体 | **只替换适配块内 `model = Xxx(...)` 的 Xxx**（例如 `TSFNet` → `TSFNetBase`）。不追加第二段适配层，不改原 class，不改加载器 |

### 5.2 只给意见、不自动改

静态扫描失败、import 失败、需联网下骨干、声明 CUDA、dummy 空间尺寸崩、带 `module.` 前缀且去前缀后键集合不能证明完全一致、以及**键名大量对不上且无法用 `model_name`+注册表对齐到源码里已有的另一个 class**。

### 5.3 不做

改网络结构、改 `.pth`、随机权重、`strict=False` 当成功、多文件折单文件、用 LLM 结论当可运行、为了对齐权重去改 `detail_separable` 等原 class 默认值（正确做法是改用源码里已经写好的变体类）。

## 5.4 现场案例：TSFNet 八消融（2026-09-20）

学生上传单文件，内含统一类 `TSFNet`（默认 `detail_separable=True`，Detail Branch 为 dw/pw）以及 `TSFNetBase` / `TSFNetTADE` / … 和 `MODEL_REGISTRY`。权重 checkpoint 为：

- `model_name = tsfnet_base`
- 键形如 `detail_branch.stage1.0.0.weight`（普通卷积）
- **没有** `*.dw.*` / `*.pw.*`，也没有 TADE/SACS 键

第一次只按「缺入口」追加时，若误包 `TSFNet()`，复检会停在 `load`（Missing `dw`/`pw`，Unexpected `stageN.0.0.weight`）。这不是权重损坏，也不是 `module.` 前缀。

正确动作：适配层改为 `TSFNetBase(in_channels=..., num_classes=...)`。错误动作：改 `TSFNet` 默认值、`strict=False`、剥 `module.`。

v0.4 起：首次追加必须读 `model_name`；若已经包错，助手必须再给出「换目标类」按钮，而不是停在「已追加过适配层，不再自动改」。

## 7. 同意后的落盘与审计

- 改 **当前** `ModelVersion` 的 `storage/models/<id>/model.py`，不另开一条「幽灵版本」。
- 通过后这条记录就是学生模型中心里的可运行版本，后续对比/评测直接选它。
- 状态：`cannot_start` → `checking` → `runnable` 或仍 `cannot_start`。
- 适配层标记：`# --- lab-adapt-begin ---` … `# --- lab-adapt-end ---`。换目标类时**替换整块**，文件中只保留一段。
- 审计：操作者、时间、版本 ID、失败阶段、同意与否、补丁摘要（含目标类）、复检结果。
- 复检失败：保留已写入源码与新报告；禁止为绿灯自动改架构或放宽加载。

## 9. 验收

- **AD-01** 缺入口：同意后不再停在「找不到 build_model」；通过则该版本在模型中心为可运行。
- **AD-02** 拒绝：源码哈希不变。
- **AD-03** diff 不改原有 class 层定义。
- **AD-04** 未复检通过不得 runnable。
- **AD-05** 白名单外无追加按钮或按钮不可用。
- **AD-06** 不能改他人私有版本。
- **AD-07** 多路输出预览写明「使用返回值第 1 项」；不得提供选路控件。A3Net 的 `return s1,s2,...` 中 `s1` 为最细分类头，与此规则一致。
- **AD-08** 同意追加的 diff 不含去 `module.` / 改 `strict` 的加载逻辑。`load` 失败且**无法**用 `model_name`+注册表对齐到另一已有 class 时，只有意见、不能靠自动按钮改权重加载。
- **AD-09** 权重带 `model_name` 且源码有注册表时，首次追加包的是映射类（如 `tsfnet_base` → `TSFNetBase`），不是统一类 `TSFNet`。
- **AD-10** 已有适配层、`load` 失败、适配块构造类与注册表映射不一致：同意后只替换适配块目标类，标记仍只有一段，原 class 字节级不变；补丁仍不含加载器改写。

## 11. 锁定说明（依据）

### `forward` 多路输出：固定第 1 项

现检查器已是「tuple/list 则取第一个张量」。A3Net 为 `return s1, s2, s3, s4, s5`，`s1` 为最细分类头。包装与检查器必须同一规则，第一版不做选路。若可视化明显不是主头，学生点「不同意」自行改后再传。指定 index 若以后做，检查器须同步，不在第一版。

### 权重 `module.` 前缀：不自动去

此前缀来自 `DataParallel`。无条件去掉会破坏单卡权重的键对齐。自动追加只包接口（`build_model` / 构造参数 / 取第 1 路输出 / 选对已有变体），不改 `load_state_dict`。增强项须满足「去掉前缀后键集合完全一致」才可自动映射，且仍 `strict=True`，禁止 `strict=False`。

### 消融变体：换类，不改统一类默认值

统一类上的开关（如 `detail_separable`、TADE、SACS）属于网络结构。源码若已提供 `TSFNetBase` 等变体，适配层必须实例化那个变体。禁止为了对齐 `.pth` 去改统一类 `__init__` 默认值，也禁止 `strict=False` 吞掉键差。
