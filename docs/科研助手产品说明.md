## 已拍板

1. **一个科研助手 + 路由 + 若干工具，不要多个 LLM Agent 互聊。** 学术问答、分割代跑、参数检测、结果分析是四类**工具**，共用一个写作模型和一层薄 harness。检测 / 分类管道落地后只加工具，不新开 Agent 进程。
2. **需要薄 harness，不引入多智能体框架。** 会话落 MySQL；工具白名单；副作用二次确认；每轮工具步数上限；证据分级；审计。不引入 CrewAI / AutoGen / LangGraph 作为运行时。
3. **意图以界面按钮为主，规则其次，LLM 闭集 JSON 兜底。** 不单独训练意图分类模型。副作用工具（入队、测速前向）必须用户确认后才执行。
4. **知识库后置。** 第一期学术问答靠导师审定阅读包 + 首页 catalog 表；不上独立向量库（不做 pgvector / Milvus）。语料变大后再评估百炼知识库或 Qdrant。
5. **MySQL 存会话与测量结果；Redis 仍只做队列 / 限额 / 缓存。** 不把对话、参数量、耗时只放 Redis。
6. **实验室能力先于对话入口。** 模型参数检测先做成模型卡 + API（可被助手以后调用）；分割代跑复用 `uploads` + `compare`，不走公开演示、不走正式评测。
7. **第一刀编码：模型参数检测。** 科研助手对话、代跑、学术问答本阶段不编码。
8. **参数量读已测事实，速度是本机墙钟，禁止写成论文 FPS。** 学生 `.py` 仍只在 Docker 内加载；API 进程不 `import` 学生源码。
9. **正式名称：科研助手。** 工具在文档与代码注释中用英文 id（见 §5），用户界面只用中文。

## 1. 要解决什么问题

登录用户希望在本站内：看懂对比/评测结果、用可运行模型对上传图做分割可视化、查看模型体积与本机前向耗时、按审定清单入门钢铁缺陷分割文献。这些事今天分散在对比页、模型卡、占位助手页，且模型卡上内置模型参数量常为空、FLOPs 恒为「未测量」。

目标：用**同一套证据纪律**把上述能力接到一个助手入口，并把「测参数 / 测本机耗时」做成可复用的实验室接口。

非目标：多 Agent 讨论、顶刊全文检索、代写网络、在线训练、把首页文献卡片当可运行模型、用公开演示冒充评测、用本机 ms/图对比论文表、LLM 证明代码安全或批准 runnable。

## 2. 本站契约（助手必须遵守）

1. 须登录。访客不可用科研助手，不可触发参数检测。
2. 无 `LLM_API_KEY` / `DASHSCOPE_API_KEY` 时：对话类工具显示不可用；**模型参数检测 API 与模型卡数值仍可用**（不依赖大模型）。对比 / 演示主流程不受影响。
3. 可运行模型 = 模型中心 `status=runnable` 且当前环境可跑（本实验室默认 CPU，`requires_cuda` 则本机不可测速）。首页 `catalog_models` 是文献条目，**不可**作为 `version_id`。
4. 分割代跑只封装实验台：`POST /api/uploads/images` → `POST /api/tasks/compare`。禁止调用 `POST /api/demo/tasks`、禁止对非 `eval_ready` 用户图走正式评测。
5. 无 GT 不得返回或口述 mIoU / mDice / Acc。公开演示任务不得分析成「正式精度结论」。
6. Web 进程不 `import` 学生 `.py`；学生检查、推理、测速均 Docker（`--network=none`）。内置模型测速可在 `lab-worker` 进程内走已有 L1 模块。
7. 证据分级：测量事实 / 规则判断 / LLM 推测 / 未知。指标与参数量、耗时只许来自工具 JSON，禁止模型口算。
8. 预处理仍为版本上的规格（默认 `neu_200`：200×200）。测速输入尺寸必须与该规格一致，禁止为刷速度改分辨率。
9. 不改变 `ModelVersion.status`。测速失败不等于 `cannot_start`。改源码只属于模型适配助手。

## 4. 架构（不要多 Agent）

```text
用户（按钮定意图 / 自然语言兜底）
    → 意图路由（闭集，见 §6）
    → 薄 harness：鉴权、白名单、确认、步数、审计
    → 工具（无独立 LLM 人格、不互相发消息）
         kb.answer        学术问答（只读）
         infer.run        分割代跑（副作用，须确认）
         perf.measure     模型参数检测（入队测速须确认；已有档案只读可不确认）
         task.analyze     分析已有对比/评测（只读）
    → 结构化 JSON（带来源）
    → 单一写作模型（可关：无 Key 则只展示 JSON/模型卡）
```

检测 / 分类真实管道就绪后：为 `infer.run` 增加 `task_type`，或增 `infer.detect` / `infer.classify`。**不**新增「检测 Agent」「分类 Agent」。

Harness 最小集：

- MySQL 存 `assistant_sessions` / `assistant_turns`（意图、工具名、参数摘要、返回摘要、关联 `task_id` 或 `version_id`）。第一刀参数检测可只写测量表，会话表随对话切片再加。
- 工具白名单即上表；禁止评测固定集、禁止演示当评测、禁止改 admit、禁止改适配层。
- 每轮最多 3 次工具调用。
- 入队类工具：先返回将执行的参数，用户点确认后再 RQ。

不把「学术 Agent 调分割 Agent 再调性能 Agent」写成实现。混合问题拆成多步计划，逐步确认。

## 6. 意图识别

闭集：`academic_qa` | `run_segment` | `run_detect` | `run_classify` | `measure_perf` | `analyze_task` | `out_of_scope`

`run_detect` / `run_classify` 在管道未就绪时路由为 `unavailable`（指向占位页），不交给写作模型假装能跑。

三层，从稳到活：

1. **按钮（主路径）**：问文献 / 跑分割 / 测效率 / 分析任务。点按钮即意图已定。
2. **规则**：附件+未点按钮 → 倾向代跑但仍确认类型与模型；带对比/评测 `task_id` → `analyze_task`；「参数量 / 多大 / 多少毫秒」+ 模型 → `measure_perf`；「读哪篇 / 入门」→ `academic_qa`；训练 / 微调 / 部署 FPS → `out_of_scope`。
3. **LLM 结构化输出（兜底）**：只输出 `intent`、`slots`、`confidence`、`clarify`。低置信或混合意图先问一句。槽位不够（未点 `version_id`）禁止猜模型。

用户说首页文献名（如 EAMINet）：澄清「文献条目不可跑」，列出模型中心 runnable 列表。

## 7. 知识库（后置，本阶段不编码）

分层检索，禁止「先建向量库再找东西塞」：

1. **协议条文（不 embedding）**：NEU-20 ≠ 论文 test split、演示无精度、无 GT 不谈精度、`strict=True`、学生代码进 Docker。关键词命中整段引用。
2. **结构化表（SQL）**：`catalog_*`、模型中心 runnable 列表。
3. **短说明（以后才 embedding）**：模型卡 detail、审定摘要。须导师确认、带来源、证据不足拒答。

不上 Postgres/pgvector（现网是 MySQL 8）。不上 Milvus。Redis 不当向量库。禁止把学生源码、权重、私有图、演示指标写入知识库。

## 8. 第一刀：模型参数检测

独立实验室能力，**不依赖科研助手对话、不依赖 LLM**。助手以后的 `perf.measure` 只调用本切片 API。

### 8.1 要测什么

| 字段 | 含义 | 来源 | 第一刀 |
|------|------|------|--------|
| `param_count` | `sum(p.numel())`，含未训练冻结与否的全部 parameter | 学生：admit 已有；内置：常空，本刀补测 | 必做 |
| `weight_bytes` | 权重文件字节数 | 磁盘 | 必做 |
| `latency_ms_per_image` | warmup 之后、batch=1、与版本 `input_h×input_w` 一致的前向墙钟，毫秒/图 | Worker 实测 | 必做 |
| `device` / `env` | 如 `cpu`，以及 platform、Python、torch 版本 | 实测环境 | 必做 |
| `input_h` / `input_w` / `warmup_runs` / `timed_runs` | 测速协议 | 固定写入档案 | 必做 |
| `flops` | 单次前向估计 | 可选库（如 fvcore）；失败则保持未测量 | 同刀尽力；允许仍为未测量 |
| 精度指标 | mIoU 等 | 不属于本刀 | **禁止**夹带 |

禁止对外文案使用「FPS」「检测速度达到 xx」「优于论文 xx」。只写「本机 CPU、指定分辨率、warmup 后 N 次的毫秒/图」。合成输入（全零或固定噪声）须在档案中标明 `input_kind=dummy`，不等于产线或论文测速。

### 8.2 谁可以测

仅 `runnable` 且当前环境可加载的版本。`cannot_start`、检查中、CUDA-only 在本 CPU 实验室：**不入队测速**；若 admit 已有 `param_count` 仍可只读展示。不可测他人私有学生版本。

### 8.3 怎么测（隔离）

```text
已有档案且协议字段齐全 → 直接读库，不重复跑
否则 → RQ 任务（与 admit/compare 同一 lab-worker）
    内置：Worker 进程内 get_builtin_module，count_parameters，dummy 前向计时
    学生：Docker 内加载，同 admit 挂载与禁网；只返回 JSON 数字，不把权重拷出
    → 写入测量表，并把 param_count 回填 Weight.param_count（若空则写，已有则核对，不一致记规则判断不覆盖admit除非差为实现误差说明）
```

协议锁定（第一刀不可配到刷榜）：

- `batch=1`，`warmup_runs=3`，`timed_runs=10`，取 timed 的平均墙钟。
- 空间尺寸 = 该 `ModelVersion.input_h/input_w`（内置为 200×200）。
- `device=cpu`。不得为测速改 `num_classes` 或预处理。
- 计时包住 `forward`（含学生包装后的主输出），不含读盘、不含着色可视化。

`Weight.param_count` 仍是参数量事实源之一；本刀新增测量档案，避免把耗时、环境塞进 `weights` 表。

建议表 `model_perf_profiles`（一版本一行，可重测覆盖并留 `measured_at`）：

- `version_id`（唯一）、`param_count`、`weight_bytes`
- `latency_ms_per_image`、`warmup_runs`、`timed_runs`、`input_h`、`input_w`、`batch`
- `flops`（可空）、`input_kind`、`device`、`env_json`
- `status`：`unmeasured` | `queued` | `measured` | `failed`
- `fail_message`、`measured_at`、`job_id`

### 8.4 页面与接口（第一刀范围）

**模型卡（必做）**

- 参数量：有数字则显示（可附 `x.xx M`），无则「未测量」，`runnable` 时提供「测量参数与耗时」。
- 权重大小：有文件则显示字节（或 MB），无文件「—」。
- 本机前向：已测显示 `xx.x ms/图` + 分辨率 + `CPU` + 测量时间；未测「未测量」。
- FLOPs：已测显示数字并标注「估计」；否则保持「未测量」（与现 UI 兼容）。
- 禁止在模型卡出现 FPS、禁止出现 mIoU。

**侧栏「性能测试」独立页：本刀不做**，避免和助手、对比抢入口。API 先稳定，页面后置。

**API 轮廓（编码时写入 OpenAPI，名称可微调）**

- `GET /api/models/{version_id}/perf`：读档案；无档案则字段为未测量，不自动开跑。
- `POST /api/models/{version_id}/perf`：对可见且 runnable 的版本入队；已 `queued` 则拒绝或返回现任务；完成后 Worker 写档案。

序列化进现有模型卡 payload：不要永远把 `flops` 写成死字符串 `"未测量"`；有档案则用档案。

### 8.5 与现码的关系

- `packages/admit/runner.py` 已在学生通过时写 `param_count`；Worker `run_admit` 回填 `Weight`。本刀不得要求学生模型在 API 进程再数一遍。
- 内置 baseline 播种时 `param_count=None`；`apps/worker/jobs.py` 对比推理时若空会 `count_parameters`。本刀应在不跑完整对比的情况下也能填内置参数量。
- `serialize_version` 的 `"flops": "未测量"` 改为读档案。
- 需求书 §9.3：效率只展示实际测到的参数量、文件大小、本次任务耗时；未测 FLOPs/FPS 显示「未测量」并注明环境。本刀的「本机前向 ms/图」属于模型档案，**不是**某次对比任务的墙钟；对比任务耗时仍按任务记录，二者不得混写为同一个数字。

### 8.6 不做

- 用 LLM 估计参数量或速度。
- 未过 admit 的学生模型静默随机权重来「也能测」。
- 为测速下载 ImageNet 预训练或联网。
- 把测量结果写入公开演示页。
- 多卡、CUDA、混合精度、量化、TensorRT。
- 一次对全库模型自动扫完（须用户或导师对指定版本触发；内置可在种子/管理操作中批量，但不在第一刀做全自动夜扫）。

## 15. 验收

### P0 模型参数检测

- **PF-01** 学生版本 admit 已通过：模型卡参数量与 admit `param_count` 一致（或测量档案与其一致）；不在 API 进程 import 该 `.py`。
- **PF-02** 内置 runnable 版本：点测量后（或入队完成）参数量不再为空，且为 `count_parameters` 同类实现。
- **PF-03** 权重大小来自文件字节，缺失文件不编造。
- **PF-04** 测速完成后展示 ms/图、分辨率、CPU、环境、`dummy` 输入说明；页面无 FPS、无 mIoU。
- **PF-05** `cannot_start` 或 CUDA-only：POST 测速被拒，原因可见；已有参数量仍只读。
- **PF-06** 不能测他人私有学生版本（403/404）。
- **PF-07** 访客测速接口未登录 401。
- **PF-08** 无 LLM Key 时 PF-01～07 仍成立。
- **PF-09** FLOPs 未实现或失败时文案为「未测量」，不得填 0 冒充已测。
- **PF-10** 协议尺寸与版本 `input_h/w` 一致；审计含操作者、版本、环境 JSON。

## 16. 成功标准（P0）

打开模型卡能看到**已测**的参数量和权重大小；对可运行模型能入队得到带环境标注的本机前向毫秒/图；数字来自 Worker/admit，不来自 LLM；学生代码隔离不被打破。

科研助手对话能「调用本站测参数」是后续切片的成功标准，不是本刀的。

## 17. 锁定说明（依据）

### 单助手而非多 Agent

三个角色权限不同（只读检索 / 副作用入队 / 读测量档案），但互聊会把文献模型与可运行模型、本机耗时与论文 FPS 搅在一起。工具隔离 + 一个写作模型即可审计。现体量不需要多智能体框架。

### 测速不是 FPS

需求书禁止未测 FLOPs/FPS 填假数字，也禁止无 GT 精度。CPU 实验室 dummy 前向只证明「这个版本在本机、这个分辨率下的墙钟」，不能当部署指标，不能进学术问答当「该模型很快」。

### 参数量以 numel 为准

与现 admit 一致，避免「只数 trainable」和「含 buffer」两套数。与 `Weight.param_count` 冲突时以 admit/测量 JSON 对照，禁止为了好看改定义。

### 第一刀不做助手对话

避免未完成路由时，聊天把未实现的检测/分类接进分割接口。参数检测先成为模型卡上的稳定事实，再给 `perf.measure` 包一层。
