## 1. 选型原则

1. 与现有分割代码同属 Python / PyTorch，减少两套语言。
2. 一台常驻 CPU 服务器能跑起来，组件尽量少。
3. 学生 `.py` 与网站进程隔离；内置 baseline 可走可信代码路径。
4. 第一版不做训练、不做微服务拆分。
5. 以后若加 GPU Worker，不必推翻 Web 与数据模型。
6. 公开演示与实验台共用本栈，用任务类型和鉴权隔离，不另起技术栈。

## 3. Web 框架

### 推荐：FastAPI + Vue 3

原因：

- 对比页要轮询任务、上传多图、返回图片 URL，适合 API 而不是纯服务端渲染。
- Worker 与 Web 本来就要拆开，FastAPI 只做 HTTP。
- 自动 OpenAPI，方便新仓库前后端并行。
- Vue 3 + Element Plus 做后台、表格、上传、图片预览在国内课题组常见。

不推荐 Streamlit/Gradio 当正式站；不推荐纯 Next.js 全栈（推理仍要 Python Worker）。

前端配套：TypeScript、Vite、Axios、任务页短轮询 2–3s。实验台图片走登录后的文件接口；演示图片走 `/api/demo/tasks/:id/file/...`（任务级授权，不是整站匿名静态目录）。

## 4. PostgreSQL 与 MySQL 在本项目中的对比

用户、模型、任务、文件路径，两种库都能存。差别不在「能不能做网站」，而在 **队列、JSON 检查报告，以及以后加 Redis 之后还剩什么优势**。

### 4.1 本站真实负载

- 写入不多：有人点「开始对比 / 正式评测 / 公开演示」才入队。
- 并发形态：Web 写入、Worker 抢任务并改状态，不是高 QPS。
- 半结构化数据：类别映射、自动检查报告、预处理协议、失败阶段。
- 图片和 `.pth` 在磁盘上，库里只存路径和哈希。

### 4.2 不加 Redis

| | PostgreSQL | MySQL 8 |
|--|------------|---------|
| 优点 | 用 `SKIP LOCKED` 当队列很常见；`JSONB` 适合检查报告；一个库同时管业务和排队 | 国内更熟、备份和图形工具多；8.0 也有 JSON 和 `SKIP LOCKED` |
| 缺点 | 课题组可能没人运维过 | JSON 查询和索引较弱；不能用 5.7 |
| 对本站 | **更适合「暂时不上 Redis、用数据库排队」** | 功能能做全，队列和 JSON 要多写一点兼容 |

生产环境不要用 SQLite：和选 Postgres 还是 MySQL 无关，多进程写任务状态会锁文件。

**不上 Redis → 更推荐 PostgreSQL。**

### 4.3 以后加了 Redis

Redis 适合拿走这些**可重建、允许短暂丢失**的事：

- 任务排队（谁先跑）
- Worker 抢锁
- 可选：推理日志尾部、进度百分比

这时「Postgres 当队列」几乎不再构成优势。两边都变成普通业务库。

| | Redis + PostgreSQL | Redis + MySQL 8 |
|--|--------------------|-----------------|
| 优点 | JSONB 仍方便存/查检查报告；和 FastAPI 示例多 | 国内 Web 常见；实验室已有 MySQL 时最省事；排队不再求助于 MySQL |
| 缺点 | 要同时维护 Postgres 和 Redis | 很少在 SQL 里拆 JSON 查询（若报告只整包读写，这点不痛） |
| 队列 | 交给 Redis，两边打平 | 交给 Redis，两边打平 |

**Redis 和两种库都兼容，不存在「上了 Redis 就必须用 MySQL 或必须用 Postgres」。**

必须坚持的职责划分：

```text
Redis            排队、锁、可选实时日志（可丢、可重建）
PostgreSQL/MySQL 用户、模型哈希、任务终态、指标、文件索引（必须持久）
磁盘             图片、权重、拼图 PNG
```

不要只把「对比已完成」放在 Redis 里。Redis 重启或缓存满淘汰后，页面应仍能从数据库打开历史结果和下载包。

### 4.4 已确认选择

**本项目采用 Redis + MySQL 8。** 对比过程见上；你已选择更熟悉的 MySQL，并用 Redis 承担队列与多级缓存。

职责：

```text
Redis     队列、锁、L2 缓存、可选日志尾部、访客演示滚动限额（限额可丢、可重建）
MySQL 8   用户、模型哈希、任务终态、指标、文件索引、demo 任务元数据（必须持久）
磁盘      图片、权重、拼图 PNG（不进 Redis）
```

访客演示限额允许 Redis 丢失后短暂多放行；**不得**把「演示是否已完成、图层在哪」只放在 Redis。`type=demo` 的 Task 行与制品路径仍写 MySQL + 磁盘。

JSON 检查报告以整列/`TEXT`/`JSON` 存储，第一版不在 SQL 里做复杂 JSON 查询。版本 **MySQL 8.0+**，不用 5.7。ORM：SQLAlchemy 2 + Alembic，MySQL 方言。

### 4.5 多级缓存（本项目怎么分层）

人数不多，缓存目标是：**对比页轮询少打库、内置模型不要每次从磁盘加载、静态资源走浏览器**。不是电商那种全站堆缓存。

| 级 | 位置 | 放什么 | 不放什么 | 失效 |
|----|------|--------|----------|------|
| L0 | 浏览器 / Nginx | 前端 JS/CSS（带 hash 的长缓存）；已完成任务的拼图可用短缓存 | 登录接口、进行中的任务 JSON | 发版换 hash；拼图 URL 含 task 版本 |
| L1 | 进程内存 | Worker 已加载的内置 `nn.Module`；Web 侧极小的本进程 LRU（可选） | 学生 `.py` 模块（必须每次在容器内加载） | 进程重启；模型下架后丢掉对应权重 |
| L2 | Redis | 工作台摘要、模型卡片列表、任务状态快照（短 TTL）、会话可选 | 原图/掩码/拼图 PNG、`.pth`、完整数据集 | 写入 MySQL 成功后删对应 key；TTL 作兜底（建议 30–120s 状态，5–30min 模型卡） |
| L3 | MySQL | 权威数据 | — | 以库为准 |

规则：

1. **读**：L1 → L2 → MySQL；命中则返回。任务状态 TTL 要短，避免页面停在「运行中」。
2. **写**：先写 MySQL，成功后再删 Redis 相关 key（Cache-Aside）。不要只写 Redis。
3. **无 GT 的任务以及所有 `type=demo` 任务** 禁止在任何缓存层塞入 mIoU/Dice/Acc 等精度字段。
4. **PNG 与权重走磁盘 + Nginx**，不要把几 MB 的图放进 Redis。
5. 学生模型推理仍每次 Docker 冷启动加载权重，避免容器之间共享内存把隔离打穿。内置 UNet 等才用 L1 模型缓存。公开演示只走 L1 内置权重，不加载学生模块。

建议 Redis key 前缀（db1，与 RQ 的 db0 分开）：

| Key | 用途 | 失效 |
|-----|------|------|
| `lab:dash:{user}` | 工作台摘要 | 写后删除；TTL 兜底 |
| `lab:models:list:{user}` | 模型列表 | 写后删除；TTL 兜底 |
| `lab:task:{id}:status` | 任务状态快照 | 短 TTL；demo 快照不得含指标 |
| `lab:demo:ip:{ip_hash}` | 访客演示限额（ZSET，score=unix） | 滚动 24h；ZREMRANGEBYSCORE |
| `lab:demo:sid:{guest_sid}` | 同上，按演示会话 | 滚动 24h |
| `lab:demo:submit:{ip_hash}` | POST 防刷计数（具体上限编码时配置） | TTL 约 1h |

`ip_hash = sha256(SECRET_KEY + client_ip)`，Redis 与 MySQL 的 `guest_ip_hash` 用同一算法。队列用 RQ 自己的 key 空间。避免 `FLUSHDB` 误伤：db0 队列、db1 缓存与限额。

## 5. 队列

已确认：**Redis + RQ**。

- FastAPI 入队；`lab-worker` 进程跑 RQ worker（同步，适合 PyTorch）。
- job 类型：`admit`、`compare`、`eval`、**`demo`**（入口建议 `apps.worker.jobs.run_demo`）。
- `demo` 只跑内置 CPU 模型，不进 student Docker；Worker 按 `task.type` 硬分支关闭指标与 GT 产物，禁止仅靠 compare 上的布尔开关隔离。
- 入队同时在 MySQL 插入 Task 行；Worker 结束必须把 `queued/running/success/failed/partial_success` 写回 MySQL。
- Redis 挂了：新任务无法入队，历史结果仍从 MySQL + 磁盘读；演示限额可能重置。
- 不推荐第一版 Celery。

限额窗口必须用 ZSET 滚动 24h，不要用 `INCR` + 86400s TTL 的固定窗口（跨午夜会整段清零，与需求「滚动 24 小时」不符）。

## 6. Worker：子进程还是 Docker

学生 `.py`：**Docker**（已安装）。`--network=none`，只读挂载代码/权重/输入，可写仅输出目录，限内存/CPU/时间，镜像预装平台 torch，禁止运行时 pip。

内置 CPU baseline：宿主机 Worker 里直接调平台 PyTorch，不必每次起容器。

不要在 FastAPI 里 `import` 学生文件。

## 8. 其他配套

Nginx 反代；systemd 管 `mysqld`、`redis`、`lab-web`、`lab-worker`、`docker`；文件在本地目录；Node 20 仅构建前端。LLM 未配置则助手页显示不可用。备份：MySQL dump + 磁盘目录；Redis 可不持久化队列与限额，但 **AOF/RDB 至少保留缓存可丢的预期**。

公网部署时 Nginx 终止 TLS，把 `X-Forwarded-For` / `X-Real-IP` 传给 FastAPI。应用只信任来自本机反代的转发头，用于演示 IP 限额；不要在无反代的开发环境盲目信任客户端自报 IP。实验台 API 不得把 8000 直接暴露公网。演示 API 免登录，必须保留限额与按 task 授权读文件。

## 9. 目标进程拓扑（已确认）

```text
[Nginx]
    ├─ /     → Vue dist（L0 静态缓存）
    └─ /api  → FastAPI
                 ├─ 读：Redis L2 → 未命中则 MySQL
                 ├─ 写：MySQL 成功后删 Redis key
                 └─ 入队：Redis RQ
                        ↓
                   lab-worker
                        ├─ L1：缓存已加载的内置 CPU 模型（compare / eval / demo 共用）
                        ├─ 内置推理（本进程；demo 只走这条）
                        ├─ docker run 学生检查/推理（不共享 L1 权重；demo 禁止）
                        └─ 终态写回 MySQL，并删 task/dashboard 缓存
```
