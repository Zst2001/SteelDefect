适用范围：课题组内部网站第一版及二期规划；本阶段只做需求分析，不编码、不选技术栈。

## 1. 文档目的

把对话中已确认的需求写成可评审、可验收的分析书，作为后续概要设计与编码的唯一功能事实源。未写入本文的能力，第一版不得自行扩展。

本文回答四件事：

1. 网站为谁解决什么问题。
2. 第一版做哪些功能、明确不做哪些。
3. 学生模型如何接入、如何与 baseline 对比。
4. 网站与 AutoDL 训练如何分工。

## 2. 项目背景

课题组研究方向为计算机视觉，主线是工业表面缺陷检测；本课题聚焦钢铁缺陷语义分割。现有仓库已具备多数据集加载、多种分割模型、统一训练与评测脚本、部分可视化脚本和已训练权重，但没有 Web 层。

学生日常在 AutoDL 租用 GPU 训练，数据集通常为数百至数千张。本机或未固定显卡的云实例不适合承担长期训练。若把整个网站部署在 AutoDL 实例上，实例关闭后知识库、科研助手、论文检索等非训练功能也会下线，因此网站必须常驻，且第一版不提供在线训练。

论文插图、框架图、组图由 Draw.io 完成。网站只需给出对齐协议后的分割对比图和可下载图层，不负责出版级排版。

后续还计划建设企业工业缺陷检测网站（基金申请展示），与课题组网站账号、数据、模型库运行时完全隔离。本需求分析书优先冻结课题组网站。

## 3. 建设目标

### 3.1 一句话目标

建设常驻在线的课题组科研网站：学生在 AutoDL 完成训练后，将模型导入网站，在同一批图片上与内置 baseline 对比分割效果，并支持有标签评测、结果留存、后续知识库与科研助手。

### 3.2 第一版成功标准

同时满足：

1. 内置 baseline 可对上传图片或预置数据集做分割推理，并生成可视化。
2. 学生导入自己的 `.py` + `.pth` 后，经自动检查即可加入对比；失败则明确提示不能启动。
3. 同一批图上，学生模型与 baseline 的分割可视化可拼接对比，并可下载。
4. 无 GT 时不算精度；有 GT 时可给出该批样本的参考指标。
5. 网站不依赖 AutoDL 开机即可访问账号、模型库、历史对比结果。

### 3.3 不作为第一版成功标准

- 在网站上启动训练或微调。
- 自动生成可直接投稿的论文图、图注、DPI/PDF 排版。
- 目标检测、图像分类真实跑通。
- 知识库、顶刊检索上线（二期）。

## 4. 需求决策冻结

| 编号 | 决策 | 说明 |
|------|------|------|
| R-01 | 两个网站完全独立 | 账号、数据、模型、任务、日志不互通。企业数据不进入课题组。 |
| R-02 | 先建课题组网站 | 企业基金原型后置，不纳入本版编码范围。 |
| R-03 | 第一版只承诺语义分割 | 检测、分类只保留并行占位页。 |
| R-04 | 不做在线训练 | 训练、续训、微调仍在 AutoDL；网站只做导入、推理、对比、评测。 |
| R-05 | 常驻 CPU 网站 | 网站不部署在 AutoDL 临时实例上。 |
| R-06 | 快速任务最多 50 张 | 仅约束快速对比上传；正式评测用完整数据集，受配额而非 50 张限制。 |
| R-07 | 模型以 `.py` + `.pth` 导入 | 不接收任意 ZIP 直接运行；单文件为主，需填写接口元数据。 |
| R-08 | 取消人工审核 | 无模型审核员；导师为最高管理员；导入后自动检查，失败即不能启动。 |
| R-09 | 仍需隔离执行 | 学生 `.py` 不得在 Web 进程内直接 import；自动检查与推理在隔离进程/容器中进行。 |
| R-10 | 对比拼图替代论文出图 | 网站生成学生 vs baseline 可视化拼接；论文排版用 Draw.io。 |
| R-11 | 无 GT 无精度 | 不得生成或估计 mIoU、Dice、准确率等。 |
| R-12 | LLM 只解释证据 | 不能证明代码安全、不能批准模型、不能替代人工看图。 |

## 5. 用户与角色

### 5.1 学生

- 注册/登录后使用本人空间。
- 上传快速对比图片及可选 GT。
- 导入本人模型（`.py` + `.pth`）并查看自动检查结果。
- 选择 baseline，发起推理、对比、正式评测。
- 查看、下载、归档本人结果；可把实验分享给指定成员。
- 不能查看他人私有数据，不能修改固定测试集，不能管理用户和预置模型。

### 5.2 导师（最高管理员）

- 拥有学生全部功能。
- 管理用户、配额、预置数据集、内置 baseline、共享模型。
- 下架异常模型、终止任务、查看审计日志。
- 管理固定测试集使用策略。
- 可将稳定学生模型设为课题组共享。

不设“模型审核员”。导师不逐份审批导入；系统自动检查通过即可被学生使用。共享到课题组范围由导师操作。

## 6. 总体方案（需求级，非实现选型）

```text
学生浏览器
    ↓
常驻网站（CPU 服务器）
    ├── 账号与权限
    ├── 数据集 / 模型库 / 对比任务
    ├── 结果与下载
    ├── 二期：知识库、科研助手、论文检索
    └── 推理服务（优先 CPU 兼容模型）

AutoDL GPU（学生自行开关）
    └── 仅用于线下训练；训练产物由学生导入网站
```

原则：

- 网站长期在线；AutoDL 关闭不影响浏览历史结果、知识库规划功能和账号体系。
- 第一版推理以 CPU 可运行的内置模型为主。
- 必须 CUDA 的模型（部分 Mamba/MorphoMoE）第一版可标记为“当前环境不可运行”，不阻塞主流程。
- 学生不需要为本网站安装 Anaconda；运行环境由服务器统一提供。

## 8. 功能需求

### 8.1 工作台  F-DASH

- 展示本人最近对比/评测任务、运行中与失败任务。
- 展示最近导入模型及自动检查状态。
- 提供入口：快速对比、导入模型、正式评测。
- 展示系统公告（维护、模型下架、测试集安排）。

### 8.2 快速对比  F-CMP（第一版核心）

#### 输入

- 每任务 1–50 张 PNG / JPG / JPEG / 无损 TIFF。
- 可选一一对应的像素级 GT 掩码。
- 必须选择：1 个已通过检查的学生模型，或仅使用内置模型做演示。
- 必须选择：1–3 个内置 baseline（建议默认 UNet、DeepLabV3+、SegFormer 或 Fast-SCNN 中实际已有权重者）。
- 提交前检查：类别数、输入通道、输入尺寸、预处理协议是否一致；不一致则阻止并说明原因。

#### 处理

- 同一批图、同一预处理、同一颜色映射、同一输出对齐方式。
- 各模型独立前向推理；一张失败不影响列出其他模型已成功结果。
- 预测掩码还原到便于对照的统一显示尺寸；保留原图下载。
- 无 GT：只生成可视化，不计算任何精度指标。
- 有 GT：计算该批样本的参考指标，并生成错误图。

#### 展示

无 GT 时至少提供两种视图，可切换：

```text
原图 | Baseline A | Baseline B | 学生模型
原图 | A 叠加     | B 叠加     | 学生叠加
```

有 GT 时增加：

```text
原图 | GT | Baseline A | Baseline B | 学生模型
原图 | GT | A 的 FP/FN | B 的 FP/FN | 学生的 FP/FN
```

交互：

- 逐张翻页、类别图例、叠加透明度。
- 多模型同步缩放，便于看边界。
- 标明样本量；有 GT 时标明“快速对比参考指标，不代表完整测试集性能”。

#### 下载（供 Draw.io 使用）

- 整组对比拼图 PNG。
- 各模型单独：彩色掩码、叠加图；有 GT 时含 GT 与错误图。
- 任务信息文本：模型名、权重量哈希、预处理、是否有 GT。
- 不提供论文栏宽、DPI 档位、PDF/TIFF 出版导出、图注生成、自动挑选“最适合发论文”样本。

### 8.3 数据集中心  F-DATA

- 预置数据集只读：与现有训练/评测入口实际支持的数据对齐（NEU、Magnetic、Severstal、BSData、Steel Pipe 等，以代码加载器为准）。
- 学生可上传私有分割数据集（图片+掩码+类别定义+划分或授权平台按固定种子划分）。
- 正式数据集不受 50 张限制，受用户存储与样本配额限制。
- 自动校验：配对、可读性、尺寸、类别值、空掩码、损坏、完全重复、跨 split 重复（无法判断则标待确认；确认泄漏则禁止进入正式评测）。
- 展示分辨率、类别分布、缺陷面积、细小/细长比例、样例预览。
- 已被任务引用的数据版本不可原地修改；修正则出新版本。
- 固定测试集：学生可发起评测，不能下载 GT 或改 split。

### 8.4 模型中心  F-MODEL

#### 内置 baseline

- 由导师维护结构与已训练权重。
- 模型卡至少含：名称版本、任务类型（语义分割）、类别映射、输入尺寸、预处理、参数量、是否必须 CUDA、历史指标来源、可用可视化类型。
- 第一版优先上线 CPU 可运行、仓库中已有权重的分割模型。

#### 学生导入

学生上传：

- 一个模型源码 `.py`（第一版以单文件为主）。
- 对应 checkpoint `.pth`。
- 表单：模型名、版本、入口类/函数、`num_classes`、`in_channels`、输入尺寸、预处理、是否必须 CUDA、适用数据集说明。

自动检查（全部通过才进入“可运行”）：

1. 文件类型与大小限制；拒绝可执行文件与嵌套压缩包。
2. 隔离保存，计算源码与权重哈希。
3. 静态扫描危险调用（子进程、网络、任意文件遍历等），阻断项直接失败。
4. 隔离环境中 import 并 `build_model` / 实例化。
5. `load_state_dict(strict=True)`。
6. dummy 前向，检查输出为 `B×C×H×W` logits，C 与声明类别数一致。
7. 可选极小样本推理冒烟。

失败状态为“不能启动”，页面显示阶段、原因、建议，并提供日志下载（对学生脱敏路径）。不出现“等待导师审批”。

通过后默认仅本人可见；导师可设为课题组共享。下架后禁止新任务，历史任务只读保留版本信息。

#### 接口约定（第一版）

- 入口返回 `torch.nn.Module`。
- `forward(image)` 主输出为未归一化分割 logits。
- 使用平台预处理与平台损失无关（网站不做训练）。
- 导入期不得访问网络、不得读训练数据、不得写任意路径。
- 不支持自定义训练循环、自定义数据加载器。
- 依赖仅允许平台白名单；缺依赖则检查失败。

### 8.5 正式评测  F-EVAL

- 在固定数据版本与 split 上，对学生模型与若干 baseline 做公平评测。
- 全员使用同一预处理与类别映射。
- 指标：mIoU、mDice、像素准确率、逐类 IoU/Dice、Precision、Recall、F1、混淆矩阵；同时记录参数量、权重大小、推理耗时及测试环境。
- 可从测试集抽取有限样本生成与快速对比相同的拼图，但不进入“论文出图”流程。
- 验证集结果与测试集结果分区，禁止混排。
- 无掩码数据不能进入正式评测，只能走快速对比的推理模式。

### 8.6 结果记录  F-REC

每次任务保存：任务 ID、创建者、图片或数据版本清单、模型与权重哈希、预处理、状态、日志、可视化、指标（仅有 GT 时）、下载包。

支持：再跑同配置、备注、归档、分享给指定成员、打包下载。

删除受权限与保留策略约束；已分享或已引用任务的物理删除需导师确认或改为归档。

### 8.7 科研助手  F-AI（第一版）

- 只分析当前用户有权查看的对比/评测结构化结果。
- 内容：数据质量、哪类/哪种尺度较弱、边界差异、协议是否一致、无 GT 时说明无法谈精度、下一步仍应在 AutoDL 上做的实验建议。
- 证据分级：测量事实 / 规则判断 / LLM 推测 / 未知。
- 不编造指标，不执行或修改学生源码，不改变模型“可运行”状态。

知识库 RAG、顶刊检索见第 10 节，不纳入第一版必做。

### 8.8 任务类型占位  F-TASK

- 语义分割：开放。
- 目标检测、缺陷分类：独立页面，说明规划中的数据格式与指标（检测为框 + mAP，分类为图级标签 + Accuracy/F1），按钮不可提交真实任务，不展示伪造指标。

### 8.9 系统管理  F-ADM

- 用户启停、配额、公告、存储与任务保留期。
- 预置数据与 baseline 发布/下架。
- 失败任务终止、孤立文件清理、审计导出。
- 管理员操作留操作者、时间、对象、原因。

## 9. 可视化与指标规则

### 9.1 必须生成的可视化

- 原图
- 彩色预测掩码
- 原图+预测叠加
- 预测边界（第一版建议有，便于看轮廓）

有 GT 时增加：

- GT 彩色掩码
- TP/FP/FN 错误图

### 9.2 明确不生成

- 出版级 PDF/TIFF、固定栏宽、图注草稿、自动最优样本集
- 无 GT 时的精度数字或“估计准确率”
- 用生成式模型改画缺陷区域
- 将公开数据集指标写成本次上传图的现场精度

### 9.3 指标

现有评测脚本可提供 mIoU、mDice、Acc 及逐类 IoU/Dice/Acc。第一版有 GT 时应展示 mIoU、mDice、逐类 IoU；Precision/Recall/F1 与混淆矩阵作为同批实现更完整，若工期紧可列为第一版增强项，但不得用 Acc 单独冒充分割效果。

效率只展示实际测到的参数量、文件大小、本次任务耗时；未测的 FLOPs/FPS 显示“未测量”，并注明环境。

## 11. 非功能需求

| 类别 | 要求 |
|------|------|
| 隔离 | 学生代码与推理不在 Web 主进程执行；默认无网络；只挂载本任务数据。 |
| 配额 | 每用户并发推理任务上限、存储上限、单任务 50 张、单文件大小上限（具体数值实现前由部署环境确定，需求上必须有上限）。 |
| 可追溯 | 模型源码哈希、权重哈希、预处理、数据清单与结果绑定。 |
| 失败可见 | 区分上传错误、接口错误、权重不匹配、资源不足、系统错误。 |
| 隐私 | 私有数据默认仅本人；企业网站数据永不进入本站。 |
| 可用性 | 常驻网站在无 GPU 时仍可登录、看历史、导入后查看检查失败原因。 |
| 诚实展示 | CUDA-only 模型在 CPU 环境必须显示不可运行，不得静默改用随机权重。 |

容量、并发、时延的具体数字当前未知，实现前需实测后再写入验收阈值，需求分析阶段不虚构。

## 12. 明确不做（第一版）

- 在线训练、续训、微调、超参搜索、NAS
- 网站部署于 AutoDL 并随实例开关
- 任意 ZIP/多文件训练包直接执行
- 人工模型审批流
- 论文出图工作台（DPI、PDF、图注、自动选图）
- 无 GT 精度、公开榜单冒充本次结果
- 目标检测 / 分类真实推理与指标
- 公网开放注册、产线相机/PLC/MES、自动质量放行
- LLM 作为安全证明或质检结论

## 13. 与现有代码资产的关系

可复用（封装为推理/评测服务，而非在网页里改脚本路径）：

- 模型构建与权重加载：`code/eval.py` 中 checkpoint 重建逻辑
- 指标：`code/utils_losses_metrics.py`
- 彩色掩码与预测保存：`code/eval.py`
- 内置结构：`code/compare/`
- 已有权重：`code/models/`

必须新建：

- 无 GT 的纯推理数据通道（现有 `DefectDataset` 强制要掩码）
- 多模型同图拼接对比
- `.py` 动态加载与隔离检查
- Web 账号、任务、下载包
- 原图尺寸与显示对齐策略（现有默认 200×200 resize，对比页需可追溯实际协议）

主训练入口 `code/train_multi.py`、`code/train.py` 第一版网站不调用。

## 14. 验收场景

**AC-01 内置模型快速推理**  
上传若干无 GT 图片，选择 1–2 个内置 baseline，得到原图/掩码/叠加/拼图，页面无 mIoU 等精度数字。

**AC-02 学生模型对比**  
导入合法 `.py`+`.pth` 且检查通过后，与至少一个 baseline 在同一批图上拼接对比，可下载拼图与单模型图层。

**AC-03 导入失败可见**  
缺入口、权重不匹配、输出通道错误、危险调用等分别显示“不能启动”及阶段原因，且不能加入对比。

**AC-04 有 GT 参考指标**  
上传配对掩码后，显示该批 mIoU/mDice/逐类 IoU 与错误图，并标注小样本参考。

**AC-05 协议不一致阻断**  
类别数或输入协议冲突的模型不能进入同一次对比。

**AC-06 隔离**  
用户不能通过改任务 ID 看到他人图片与结果。

**AC-07 无训练入口**  
界面不提供新建训练、续训、微调。

**AC-08 占位页**  
检测、分类页可打开但不可提交任务，无伪造指标。

**AC-09 常驻可用**  
无 GPU、无 AutoDL 时，仍可登录并查看历史对比（CUDA 模型新任务除外）。

## 16. 术语

| 术语 | 含义 |
|------|------|
| 语义分割 | 为每个像素预测类别；本站第一版唯一真实任务。 |
| 快速对比 | ≤50 张图的学生模型 vs baseline 可视化拼接。 |
| 正式评测 | 固定测试集上的全量指标对比。 |
| GT | 像素级真实掩码；模型预测不是 GT。 |
| 可运行模型 | 自动检查全部通过、未被下架的模型版本。 |
| 对比拼图 | 同一样本多模型可视化水平/网格拼接，供肉眼判断和 Draw.io 取用。 |
| 工业缺陷检测 | 产品总称；第一版实现为分割，不是检测框。 |
