## 2. 为什么建设这个项目

### 2.1 对外：展示课题组方向与已有能力

网站承担实验室介绍、工业缺陷检测方向展示、学术交流和横向合作展示等需求。访客可以免登录看首页，并用平台提供的钢铁样例体验真实模型的分割可视化。

公开演示的目标是让人看到模型如何产生掩码、叠加图和多模型对照；它不提供正式精度结论，不承担产线质量放行。

### 2.2 对内：让学生复用一套公平、可追溯的实验台

学生在 AutoDL 上训练模型后，通常需要反复加载权重、统一预处理、与 baseline 对照、整理可视化和指标。网站把这些操作组织成统一流程：

1. 上传训练好的模型源码和权重。
2. 自动进行静态扫描、隔离加载和输出形状检查。
3. 通过后在本人实验台运行，与内置 baseline 对照。
4. 无标注时看图；有配对标注时看本批参考指标。
5. 在平台固定 NEU-20 上进行正式评测。
6. 保存结果、记录配置、下载图层包、向导师提交实验台结果。
7. 用科研助手解释已有证据，或检索导师审定的学术知识。

### 2.3 使用者与权限

| 角色 | 能力 | 边界 |
|---|---|---|
| 访客 | 首页、登录、限次公开演示 | 不上传自有图片，不导入学生模型，不访问他人私有任务 |
| 学生 | 导入本人模型、上传实验图片、对照、评测、看记录、使用科研助手 | 账号由导师开通；学生之间私有任务互不可见；固定测试集 GT 不可下载 |
| 导师 | 开通／启停学生账号，查看学生提交的结果，维护获授权的站点内容 | 不能把所有需求书中的后台能力都视为已实现；学生模型自动检查不等于人工审批流程 |

学生导入通过后“本人可运行”与导师将权重审定为“平台内置模型”是两件事。前者不自动进入公开演示，也不自动开放新场景。

## 3. 当前三种使用协议：必须分清

| 项目 | 公开演示 | 快速对照 | 正式评测 |
|---|---|---|---|
| 用户 | 访客或登录用户 | 登录用户 | 登录用户 |
| 数据来源 | NEU-20 预备样例 | 用户上传本批图片，可选配对掩码 | 预置 NEU-20 固定测试集 |
| 数量 | 每次 1–5 张，从 20 张样例中选 | 每次 1–50 张 | 固定集全量 20 张 |
| 模型 | 仅内置模型，每次 1–3 个 | 1–3 个内置 baseline，可选 1 个通过检查的学生模型 | 内置 baseline 与可选学生模型，当前内置集合可全选 |
| 是否允许学生代码 | 否 | 允许，必须经过 Docker 隔离 | 允许，必须经过 Docker 隔离 |
| 指标 | 永不计算、存储或展示精度 | 仅配对 GT 齐全时给本批参考指标 | 全量固定集真实指标 |
| 主要结果 | 原图、预测掩码、叠加、拼图 | 同左；有 GT 可增加 GT 和错误图 | 固定集指标；默认抽 8 张生成拼图 |
| 结论口径 | 公开演示，不代表测试集性能 | 本批参考，不代表完整测试集性能 | NEU-20 不等于论文完整 test split |

补充规则：

- 未登录演示受 IP 和浏览器会话双重限制：滚动 24 小时内 3 次成功入队。不能通过仅清 Cookie 绕过 IP 约束。
- 登录后打开 `/demo` 仍执行演示协议，不计访客这 3 次限额，但也不转成有 GT 的实验台任务。
- 无 GT 对照的指标接口返回 `{"available": false}`，不能凭图像观感估计精度。
- 演示不写 `MetricSet`；访问其指标接口应得到 `404 DEMO_NO_METRICS`，不是零分或空指标表。
- 固定集 GT 下载对学生返回 `403 GT_FORBIDDEN`。
- 分割主要指标是 mIoU、mDice、逐类 IoU；Acc 仅在详情，不作为主结论。
- 默认 NEU 分割类别为背景、夹渣、斑块、划痕，共 4 类。
- 默认预处理为 200×200，配置含 CLAHE 与椒盐处理参数；任务应保存预处理协议，不得静默变更尺寸或处理方式。
- 下载包用于后续 Draw.io 等排版，包含拼图、单层 PNG 和 `task.json`；不提供 `metrics.json`、出版级 PDF/TIFF、自动图注或自动精选论文样本。

## 5. 技术架构与数据流

### 5.1 技术栈

| 层 | 技术 | 主要职责与边界 |
|---|---|---|
| 浏览器应用 | Vue 3、Vite、TypeScript、Element Plus、Vue Router、Axios | 页面、上传、任务轮询、可视化、助手对话 |
| API | Python 3.11、FastAPI、Pydantic、Uvicorn | 鉴权、协议校验、元数据、任务提交、文件授权，不在请求中直接执行学生模型 |
| 持久化 | MySQL 8、SQLAlchemy 2、Alembic | 用户、模型版本、任务终态、指标、文件索引、审计和助手记录 |
| 队列／缓存 | Redis、RQ | 排队、缓存、限额；不存原图、PNG 或 `.pth` |
| Worker | RQ SimpleWorker | 不 fork，适配 Windows；执行模型检查、推理、可视化与测参 |
| 内置推理 | PyTorch CPU、OpenCV、NumPy 等 | 可信内置网络在 Worker 进程内运行，可缓存已加载模型 |
| 学生隔离 | Docker，镜像 `steel-lab-student:cpu` | 静态扫描后在容器中加载和前向，`--network=none`，代码／权重受限挂载 |
| 大文件存储 | 本地文件目录 | 原图、掩码、权重、日志和结果制品，数据库记录索引及哈希 |
| 学术向量检索 | 远程 Milvus，`pymilvus` | 只允许 `ippilab`；本仓库不部署 Milvus／pgvector |
| 写作／向量化 | 火山方舟接口 | 写作与 embedding 为独立模型配置；密钥只放本地环境配置 |

这是模块化单体配合独立 Worker 的结构。当前规划应尽量复用已有模块，不应默认重写为微服务、更换数据库或换前端框架。

### 5.2 一次推理如何完成

1. 浏览器提交样例选择或上传批次及模型版本。
2. FastAPI 校验用户权限、任务协议、模型可运行状态、预处理和数据条件。
3. API 保存任务元数据到 MySQL，将任务标识交给 Redis/RQ。
4. Worker 读取任务：内置模型走可信进程内路径；学生模型交给 Docker runner。
5. 推理生成分割结果和可视化；只有允许计算指标的实验台任务才进入指标计算。
6. 文件保存到磁盘，任务终态、制品索引和允许的指标保存到 MySQL。
7. 前端轮询任务并通过授权接口展示／下载结果。

Redis 不是历史结果的唯一保存位置。队列或缓存丢失不应使已落库、已落盘的结果记录消失。

## 6. 学生插件契约与扩展边界

### 6.1 当前实际支持的分割插件

- 输入资产：一个 `.py` 源码文件和对应 `.pth` 权重。
- 推荐入口：`build_model(num_classes, in_channels=3, **kwargs) -> nn.Module`；也支持按表单指定模块类。
- 主输出：浮点 `B×C×H×W` logits，C 与声明类别数一致；预测对类别维做 argmax。
- 分割多路 tuple/list 输出按已锁定规则取第 1 项作为主输出，不自动猜测其他分支。
- 权重按允许的 checkpoint 结构装载，常见键为 `model_state` 或 `state_dict`；使用 CPU 加载，学生模型严格匹配权重。
- 检查包括文件保存与哈希、静态扫描、隔离 import／构建、`load_state_dict(strict=True)` 和 dummy 前向形状检查。
- 失败是“不能启动”，并给出 `fail_stage`、原因与日志。不能用 LLM 判断替代隔离运行成功。
- GPU 上成功不代表本机 CPU 可运行。CUDA-only、缺依赖或需联网下载的模型不得伪装成可运行。

### 6.2 已登记但尚未编码的新契约

| 算法任务 | forward 主输出 | 对应标注 | 规划指标 | 当前状态 |
|---|---|---|---|---|
| 语义分割 | `B×C×H×W` logits | 像素掩码 | mIoU、mDice、逐类 IoU | 已实现，仅钢铁 |
| 目标检测 | 长度为 B 的列表，每项为 `boxes/scores/labels` 字典 | 检测框和类别 | mAP@0.5 | 契约已登记；runner、Worker、指标未实现 |
| 缺陷分类 | `B×K` logits | 每张图一个类别 id | Accuracy、macro-F1 | 契约已登记；runner、Worker、指标未实现 |

检测的具体约定：

- `boxes`：float32 `[N,4]`，格式 xyxy，坐标对应送入模型的图像像素。
- `scores`：float32 `[N]`；`labels`：int64 `[N]`，类别 id 为 `0..num_classes-1`。
- `N=0` 合法。B=1 时仍返回长度为 1 的列表。
- 框标注文件使用 JSON 还是文本尚未决定，留待对应切片启动时确认。

每次导入只声明一种算法任务。形状不符必须失败，不能把分割 logits 的 argmax 当成检测框，也不能把分割指标当成分类指标。无对应标注时 `available=false`；任何未来公开演示仍不得写精度。

**获得新权重只是必要条件，不会自动完成新任务接入。** 新任务还涉及契约检查、Worker 分支、数据格式、结果可视化、指标、权限与验收。必须等用户明确启动相应范围。

## 7. 模型适配助手：独立于科研助手

模型适配助手出现在本人导入失败的模型版本中。它解决“训练代码接口与网站入口不一致”，不负责重新设计网络或训练。

现有流程：失败诊断 → 展示允许的适配方案和 diff → 用户同意 → 修改当前模型版本的适配层 → 更新哈希 → 重新隔离检查 → 根据实际结果更新状态。

可以处理的例子：缺入口、构造参数不匹配、多路输出取第 1 项、依据 checkpoint 的 `model_name` 和源码注册表选择已存在的正确消融变体。

必须保留的限制：

- 不改原网络 class，不改 `.pth`，不重训。

## 14. 给 ChatGPT 的分析与规划规则

本节是使用本文进行后续分析的建议格式，不是新的开发授权。

### 14.1 先按状态分类，再谈优先级

将所有提议归入以下类别之一：

1. **已实现并应保留**：例如钢铁分割主链路、公开演示、已有科研助手与 RAG。
2. **明确暂缓／当前禁止**：例如无审定 CPU 权重时开放检测、分类、PCB、光伏真实任务。
3. **需求已写但实现待核验**：例如完整数据治理和后台运维能力。
4. **条件满足后可讨论**：例如用户明确提供新权重后，对应任务的最小接入切片。
5. **新增建议，尚未决策**：必须标明推测、收益、成本及与现有边界是否冲突。

### 14.2 任务规划应包含的字段

| 字段 | 要求 |
|---|---|
| 问题和目标 | 用户会在哪个具体流程遇到什么问题，完成后有什么变化 |
| 当前证据 | 引用本文章节或后续核验的源码／测试；区分事实、推测、未知 |
| 优先级理由 | 对当前目标的价值、风险、依赖；不能只按功能听起来“先进”排序 |
| 前置条件 | 用户决定、权重、标注、CPU 验证、数据权限等是否已经具备 |
| 最小范围 | 页面、API、服务、Worker、数据模型、测试中实际需要改哪些 |
| 不改范围 | 明确应保持的分割链路、演示协议、隔离、首页、RAG 等 |
| 验收标准 | 可观察、可测试；精度只能来自真实数据与标注，不设虚构达标数字 |
| 风险与回退 | 可能影响现有能力的点，如何保留旧行为或回退 |

不要仅生成“完善前端、优化后端、增加 AI”这样的泛化清单。避免为了规划完整而把所有长期愿景都塞入近期迭代。

### 14.3 未来接入新算法时的条件顺序

只有用户明确启动相应范围后，才讨论以下步骤：

1. 确认场景、算法任务种类、使用对象和是否仅实验台。

3. 验证本机 CPU 能严格加载和前向；不通过就保留不可运行状态。
4. 确认实际标注和数据格式，无标注只做可视化，不编精度。
